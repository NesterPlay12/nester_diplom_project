# Доступ к реальным ПВЗ и границы доставки

## Текущий режим — демонстрация по решению владельца

В основной ветке владелец отменил подключение реальных операторов.
`DELIVERY_DEMO_MODE=True` сохраняется: карта показывает демонстрационные точки
с привязанными парами адрес/координаты, сервер проверяет их идентификаторы
и город, а заказ помечается «ДЕМО — не для реальной доставки».
Доступ к API операторов для демонстрации не требуется.

Ниже описан сохранённый, но не активный путь интеграции с реальными операторами.
Включать его и запрашивать production-доступ следует только по новому прямому
запросу владельца. Проверки официального каталога изолированы от демо-режима.

## Доступ операторов

- СДЭК: нужны production-реквизиты владельца договора в Secrets
  `CDEK_CLIENT_ID` и `CDEK_CLIENT_SECRET`. Значения нельзя отправлять в чат,
  включать в код или логи.
- Каталог вызывается сервером по `https://api.cdek.ru/v2`.
  Публичные тестовые реквизиты из документации не заменяют production-доступ.
- Почта России: пока не подтверждён доступный владельцу договора API каталога,
  возвращается явная недоступность. Один токен `POCHTA_API_TOKEN` сам по себе
  не подключает каталог. Нужны документация метода, условия доступа и схема
  авторизации, после чего секреты запрашиваются через защищённую форму.
- Для настоящей доставки персональные, неофициальные, собранные со сторонних
  сайтов и вымышленные базы адресов не используются. Демонстрационные точки
  не объявляются действующими офисами операторов.

## Что подтверждают проверки

Официальный контракт сверяется с https://apidoc.cdek.ru/:
`GET /v2/location/cities`, `GET /v2/deliverypoints`,
`POST /v2/oauth/token`. Офисы имеют статус `ACTIVE/CLOSED`; обязательного
названия в OfficeDto нет, поэтому при его отсутствии используется подпись
из кода офиса, а не придуманное название.

Изолированные проверки с синтетическими HTTP-ответами:

```sh
cd flask-app
python -m unittest discover -s tests -v
node --test tests/delivery-map.test.cjs
```

Они проверяют пагинацию, одноимённые города и уточнение региона,
координаты/адреса, закрытые офисы, ошибки API, свежую серверную проверку
при оформлении, сохранность корзины и остатка при отказе, а также ответы
поиска, пришедшие не по порядку. Это **не проверка живого API**.

## Приёмка после предоставления доступа

1. Подключить production-доступ через Secrets и перезапустить сервис.
2. Проверить реальный каталог для нескольких городов и регионов, включая
   одноимённые населённые пункты. Сверить адреса и координаты с оператором.
3. Для многостраничной выдачи сравнить число полученных записей с ответами
   оператора; проверить `X-Total-Pages` и последнюю страницу.
4. Проверить отсутствие точек при неверном доступе и сбое API, без возврата
   сохранённого успешного каталога как подтверждения нового заказа.
5. В изолированном тестовом заказе проверить повторную серверную проверку:
   клиентский адрес не является источником истины, удалённый/закрытый пункт
   отклоняется, а при отказе корзина и остаток товара не меняются.

## Заказ в WildMarket — не отправление

Текущий checkout сохраняет заказ только в базе WildMarket. Он не создаёт
накладную, трек-номер или отправление в системе перевозчика. Сумма товаров
не включает подтверждённую цену доставки.

Реальную отправку и расчёт стоимости нужно отдельно согласовать с владельцем:
оператор и договор, отправитель и место отгрузки (включая нескольких продавцов),
тарифы, вес/габариты, плательщик доставки, наложенный платёж, отмены и возвраты.
После согласования нужна отдельная реализация с обработкой ошибок и защитой
от повторного создания отправлений. Успешный HTTP-ответ на регистрацию у
СДЭК сам по себе не подтверждает создание: требуется итог обработки запроса.
